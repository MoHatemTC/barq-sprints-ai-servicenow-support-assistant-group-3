# BARQ G3 · Sprint 2 (S2.4) — AI Agent Reasoning & Grounded Generation

The reasoning core of the **AI ServiceNow Support Assistant**. Given an incident and the
knowledge chunks returned by retrieval, it produces a **numbered, cited resolution
procedure built only from those chunks** — or **cleanly declines** when grounding is missing.
It only *recommends*; it can never resolve, close, or reassign an incident.

```
incident + retrieved chunks
        │
        ▼
 normalize chunks ── none usable? ──► deterministic clean decline (LLM not called)
        │
        ▼
 prompt = SYSTEM rules → <knowledge_base> → <incident_data trust="untrusted">
        │
        ▼
 LangChain AgentExecutor (tool-calling loop, max iterations, read-only mock tools)
        │
        ▼
 validate_output()  ── fail-closed: every step must cite a retrieved article
        │
        ▼
 AgentResult(status = GROUNDED | DECLINED, text, cited_articles, ...)
```

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # then fill in LLM_API_KEY, LLM_MODEL, LLM_BASE_URL
python -m support_agent grounded_vpn                   # one live run
python scripts/run_samples.py                          # regenerates docs/sample_runs.md from LIVE runs
python -m pytest                                       # or: python -m unittest discover -s tests -t .
```

```python
from support_agent.agent import generate_recommendation

result = generate_recommendation(incident_dict, retrieved_chunks)   # chunks: list of dicts
print(result.status)          # "GROUNDED" | "DECLINED"
print(result.text)            # validated text for the human support agent
print(result.cited_articles)  # e.g. ["KB0010234"]
```

A chunk is `{"article_number": "KB0010234", "title": "...", "content": "...", "chunk_id": "1", "score": 0.91}`
(`chunk_id`, `score` optional).

## Configuration (environment variables only)

| Variable | Required | Purpose |
|---|---|---|
| `LLM_API_KEY` | yes | API credential (never logged; hidden from `repr`) |
| `LLM_MODEL` | yes | model name served by the endpoint |
| `LLM_BASE_URL` | for non-default endpoints | OpenAI-compatible endpoint URL |
| `LLM_TEMPERATURE` | no (default `0`) | `none` for models that reject the parameter |
| `LLM_TIMEOUT_SECONDS`, `LLM_MAX_RETRIES`, `AGENT_MAX_ITERATIONS` | no | 60 / 2 / 5 |

`.env` is git-ignored; only `.env.example` is committed. A unit test scans the source for
hardcoded keys/endpoints. The client is `langchain-openai`'s `ChatOpenAI`, so any
OpenAI-compatible endpoint works; swapping providers means changing only `build_llm()`.

## Requirement traceability

| Brief requirement | Where / how |
|---|---|
| LangChain agent executor on a live endpoint, config from env | `agent.py` (`build_llm`, `build_agent_executor`), `config.py` |
| Strict grounding: steps only from retrieved chunks | `prompts.py` §3 + `validation.py` (every step must cite a retrieved article; unknown citation ⇒ decline) |
| Numbered procedure + citation by number/title | `prompts.py` §4 (`[KB0010234]` after each step, `Sources:` list with titles) |
| Cannot resolve / close / reassign; recommendations only | `prompts.py` §1; additionally **no such tool exists** in `tools.py` (read-only tools only) |
| Knowledge **before** incident; incident in a labelled untrusted block | `HUMAN_TEMPLATE` + `formatting.py`: `<knowledge_base>` first, then `<incident_data trust="untrusted">`; escaping prevents block break-out; tests assert ordering |
| Clean decline when no relevant chunks | exact decline text in `prompts.py` §5; deterministic guard in `agent.py`; validator canonicalises any decline |
| Callable function with mock data | `generate_recommendation(incident, chunks)`; mocks in `mock_data.py` |
| Four integration tools (mock OK) | `tools.py`: `get_incident_details`, `get_incident_work_notes`, `get_kb_article`, `list_provided_articles` |
| Documented sample runs (grounded + decline) | `docs/sample_runs.md` (generated by `scripts/run_samples.py`) |

## Design decisions worth reviewing

1. **Defence in depth, not prompt-only.** The prompt asks for grounding; `validation.py`
   *verifies* it and fails closed. A model slip (uncited step, invented `KB` number, missing
   status line, iteration-limit message) becomes a clean decline instead of an unsupported
   recommendation reaching a human agent.
2. **Two ways to decline.** Empty retrieval declines *without* calling the LLM (cheap,
   deterministic, no credentials needed). Irrelevant retrieval is declined by the LLM per the
   prompt (`decline_irrelevant_chunks` scenario). `short_circuit_on_empty=False` lets the
   prompt alone handle the empty case (`decline_no_chunks_prompt` scenario).
3. **Untrusted-input isolation.** Field whitelist (e.g. `caller_name` is never sent), control
   characters stripped, 4 000-char cap, and `<`/`>` escaped so incident text cannot forge
   `</incident_data>` or a fake `SYSTEM:` block. The prompt tells the model to ignore
   instructions found in incident text, tool output, or article text. Tool output built from
   user-written content is wrapped as untrusted too.
4. **Tools are read-only and request-scoped.** `get_kb_article` refuses any article not
   retrieved for this request, so tools cannot smuggle in ungrounded knowledge.
5. **Citation format is by article number** (`[KB0010234]`) so it is machine-checkable; titles
   appear in the `Sources:` list.

## Known limitations / next steps

- The validator proves steps are *cited to a retrieved article*; it cannot prove the wording
  is a faithful copy of that article. Sprint follow-up: an entailment / string-overlap check.
- Injection resistance is strong but not absolute for any LLM; the read-only tool surface and
  human-in-the-loop review are the backstops.
- Tools are mocked. Wire them to ServiceNow / the retrieval service when available.
- LLM outages raise exceptions (deliberately not converted to a "decline").
